Social card design — 3 approaches

Each keeps Nano Banana for photo generation. The difference is how the branded card layer gets composed.

A

Pencil MCP — fully automated

Nano Banana generates the photo. Pencil composes the social card (brand colors, logo placement, text zone, border treatments) in a .pen file. Claude Code runs the whole pipeline end-to-end — one prompt, full output.

Pros

  • Zero context switching — everything in Claude Code
  • Fully repeatable, version-controlled output
  • Scales — add new card templates without learning new tools

Cons

  • Pencil is optimized for UI/web, not graphic design — social cards are at the edge of its comfort zone
  • Requires building card templates in Pencil's format upfront
  • Less visual polish control vs. Figma
B

Figma templates — industry standard

Build master social card templates in Figma once (with defined photo zones, logo, text areas, brand colors). Nano Banana photo drops into the template — manually or via Figma API. Figma exports at correct dimensions.

Pros

  • Industry gold standard for social card design systems
  • High visual polish, pixel-perfect control
  • Team members can update text/photos without a designer
  • Figma has native social template infrastructure

Cons

  • Context switch out of Claude Code for card composition
  • Requires someone comfortable in Figma to set up templates
  • Not fully automated — manual photo swap step
C

Hybrid — Figma templates + Pencil for generation

Design the master card templates in Figma (one-time setup, full design control). Claude Code + Pencil reads those templates and generates card variants programmatically — dropping in the Nano Banana photo, swapping text, exporting per platform.

Pros

  • Best of both: Figma's design quality + Pencil's automation
  • Template changes happen in Figma (visual, accessible to team)
  • Card generation stays in Claude Code workflow
  • Most scalable long-term

Cons

  • Most setup work upfront (two tools to configure)
  • Pencil → Figma integration needs to be wired up
  • Slightly more complex workflow to document

My recommendation → C (Hybrid)

Design the card templates in Figma where a human can see and control the visual output. Then let Pencil + Claude Code handle the repetitive work of generating card variants for each platform and post. This keeps design quality high without requiring a designer every time a new post goes out.

That said — if the goal is to minimize tools and keep everything inside Claude Code, Option A is perfectly viable. Pencil can produce clean, consistent social cards once the templates are defined.
